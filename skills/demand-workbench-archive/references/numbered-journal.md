# 可选兼容：固定编号编辑同步

日常记录不需要编号。用户选择“直接输入文案就上传”时，使用SKILL.md的直接日志模式，内部生成编号，不要求其采用本页格式。本页仅说明主动使用固定编号的兼容入口。

前提：已授权归档、安装此版本 Skill、后端包含 `V202611210100__codex_note_links.sql` 和两个新 MCP 工具。密钥具备 notes:read、notes:create、notes:update；配图另需 notes:upload。

首次发送：

```text
[日志:abc123]
今天第一次尝试记录日志。
```

在 Codex 中编辑这条已发送消息，保留编号，重新发送：

```text
[日志:abc123]
今天第一次尝试记录日志，已补充编辑结果。
```

网站更新同一条私密笔记，不展示编号，标题为空，Markdown 原样保存。只保存日志正文及用户明确附件，不夹带助手回复。不同日志用新编号；编号为6–64位英文、数字、下划线或连字符，区分大小写。没有编号的普通聊天保持原归档方式，不自动接管历史记录。

编号只在同一账号、项目、会话下匹配。新会话、新编号或不同项目新建记录。默认项目标识为本机项目根目录摘要；跨目录共享时可在 `.codex/archive.local.json` 中设置稳定 `project_id`，建立映射后不可随意修改。网站手工编辑、公开、移入回收站或另存编辑副本后自动修改会被拒绝。

编辑框内尚未发送的内容不会触发同步；必须重新发送并完成本轮 Skill 操作。离线跳过，不积压、不补传；上一版仍在保存时不排入覆盖任务。图片默认保留原图，明确替换或清空时才使用 image_mode；替换图片核验失败仍保留原图并保存文字。

编程入口沿用 `archive.py gate` / `publish`。提交普通 question/answer JSON 时，脚本自动识别 question 开头的日志编号；也可用 mode=numbered_journal、journal_text=完整带编号日志。submission_id 同次提交复用，编辑产生新修订编号，日志编号保持不变。不可为更新失败生成新日志编号重试。
